# 高等数学阶段性测试题库 · 开发方案

> 版本：v1.0（需求与技术选型已确认）
> 目标：面向高等数学阶段性测试复习的本地题库系统，提供「AI 题库刷题」与「真题演练」两种模式。

---

## 0. 已确认的关键决策

| 决策项 | 结论 | 影响 |
|---|---|---|
| 运行形态 | **本地单机 Web 应用**（local-first） | 无需用户体系/鉴权/并发控制；数据存本地 SQLite，单文件备份 |
| AI 接入 | **DeepSeek API**（OpenAI 兼容协议） | 统一 Provider 抽象；出题、判分、真题 OCR 均走此通道 |
| 真题素材 | **PDF / 图片扫描件** | M4 必须包含「多模态提取 → LaTeX → 人工校对」环节 |
| 技术栈 | **Python(FastAPI) + React/Vite + SQLite** | 后端 Python 的核心价值是 SymPy，用于题目正确性验证 |

**技术栈选型的唯一决定性理由**：SymPy。题目正确性验证是本产品的生命线，JS 生态的符号计算能力（mathjs / nerdamer）与 SymPy 差距达一个量级。因此后端必须用 Python。

---

## 1. 产品定性：一个内核 + 两种模式

两个模式表面差异大，但共享同一套内核：**Question / Attempt / Mistake**。

| 维度 | 题库刷题 | 真题演练 |
|---|---|---|
| 题目来源 | AI 按知识点实时生成 + 题目池复用 | 固定成套试卷（导入 / 录入） |
| 反馈方式 | 逐题即时 / 整组延迟 | 交卷后统一判分 |
| 有无总分 | 无，仅正确率 | 有卷面总分，按题给分 |
| 计时 | 可选 | 模拟考试计时 |

**架构原则**：统一的题目与作答内核 + 两个「会话策略（Session Strategy）」插件。

**核心闭环（本产品真正的价值）**：
```
真题演练 → 暴露薄弱知识点 → 一键跳转刷题模式针对补强 → 掌握度回升 → 再练真题
```
两个模式必须是打通的，而不是两个孤立功能。

## 2. 地基：知识点体系与知识点卡片

需求原文「AI 根据考察的基础要点出题」——成败全在**基础要点从哪来**。只把「极限」二字交给模型，出题必然超纲、漏考点、质量不稳。

### 2.1 知识点编码（两层）

```
HS.C1  函数、极限与连续
        C1.1 数列极限的定义与性质
        C1.2 函数极限 / 左右极限 / 无穷小阶的比较
        C1.3 两个重要极限
        C1.4 连续性与间断点分类
        C1.5 闭区间上连续函数的性质
HS.C2  导数与微分
HS.C3  微分中值定理与导数应用
HS.C4  不定积分
HS.C5  定积分及其应用
HS.C6  微分方程
HS.C7  向量代数与空间解析几何
HS.C8  多元函数微分学
HS.C9  重积分
HS.C10 曲线积分与曲面积分
HS.C11 无穷级数
HS.C12 证明题 / 综合专项
```

### 2.2 知识点卡片（YAML，直接作为 AI prompt 素材）

```yaml
id: C1.2
name: 函数极限与无穷小阶的比较
syllabus:                      # 大纲要点原文
  - 极限的唯一性、局部有界性、保号性
  - 无穷小的比较：高阶 / 同阶 / 等价 / 阶的估计
typical_archetypes:            # 典型考法：出题时轮询，保证题型覆盖不重复
  - 用等价无穷小替换求极限
  - 已知极限存在反求参数
  - 判断无穷小的阶
pitfalls:                      # 易错点：直接转化为选择题的干扰项
  - 加减法中滥用等价无穷小替换
  - x→0 与 x→∞ 的结论混用
prerequisites: [C1.1]
difficulty_range: [1, 4]
```

**`typical_archetypes` 与 `pitfalls` 是本项目最核心的资产**：
- `archetypes` 保证题型覆盖，避免"10 道题都是同一个套路"
- `pitfalls` 保证选择题的干扰项是**有意义的典型错误**，而不是模型凑数的随机选项

> **落地策略**：第一版只把 **C1（极限与连续）** 写到完整可用，跑通全链路，再横向铺开其余章节。

## 3. 数据模型

### 3.1 Question（题目）

```jsonc
{
  "id": "...",
  "source": "ai | real_exam",
  "type": "single_choice | multi_choice | fill_blank | solution | proof",
  "stemLatex": "...",                        // 全链路 LaTeX，禁止图片/纯文本公式
  "options": [
    { "key": "A", "latex": "...", "isCorrect": false,
      "rationale": "对应典型错误：加减法中滥用等价无穷小替换" }
  ],
  "answer": { "kind": "choice | value | expression | text", "latex": "..." },
  "solution": {
    "steps": [{ "title": "第一步：判断类型", "latex": "...", "note": "..." }],
    "finalAnswerLatex": "..."
  },
  "knowledgePoints": ["C1.2"],
  "difficulty": 3,                            // 1..5
  "archetype": "等价无穷小替换求极限",          // 去重与覆盖统计的维度
  "verification": {
    "status": "pass | warn | fail",
    "methods": ["sympy", "numeric", "llm_crosscheck"],
    "report": "..."
  },
  "fingerprint": "sha1(归一化题干 + 归一化答案)",  // 精确去重
  "embedding": [],                             // 近似去重
  "stats": { "attempts": 0, "correct": 0, "avgTimeSec": 0 },
  "flags": { "userReported": false, "manuallyReviewed": false }
}
```

### 3.2 其余实体

- **KnowledgePoint**：id、层级、名称、卡片正文（YAML 反序列化）
- **PracticeSession**：范围配置、题型、反馈模式、是否计时、状态、结算报告
- **Attempt**：sessionId、questionId、用户答案、是否正确、耗时、错因归类
- **Mistake**：attemptId、复习阶段（Leitner box）、下次复习时间、是否已掌握
- **Mastery**：kpId、掌握度分值、更新时间、样本量
- **Paper**：名称、年份、学校/考试类型、总分、时长、题目结构（题号→题型→分值→知识点）
- **PaperRun**：paperId、作答记录、得分、用时、历史对比

## 4. AI 出题流水线（最大风险点）

**这是整个项目唯一的真实风险**：AI 生成的数学题答案错了，用户信任崩塌一次就没了。
因此必须是「生成 → 验证 → 入库」，绝不能「生成 → 直接给用户做」。

```
① 选题：知识点 + 目标难度 + 排除近期做过的 fingerprint + 按 archetype 轮询
        ↓
② 结构化生成：JSON Schema / function calling 强约束，temperature 0.3~0.7
        ↓
③ 独立重解自检：不看答案重新解一遍，比对不一致 → 打回重生成
        ↓
④ SymPy 符号验证：
     求极限 / 求导 / 积分 → SymPy 独立计算，判定 simplify(ans − claimed) == 0
     超时则退化为多点数值采样
     选择题 → 验证唯一正确项 + 每个错误项确实为假
        ↓
⑤ 数值代入检验：随机取参数代入比对
        ↓
⑥ 去重：fingerprint 精确匹配 + embedding 相似度阈值（同 archetype 内）
        ↓
⑦ 入库分级：
     pass → 直接发放池
     warn → 低优先发放 + 进入人工抽检队列
     fail → 丢弃
```

### 4.1 题目池（Pool）—— 关键设计

**不要每次实时生成。** 为每个 `知识点 × 难度 × 题型` 维护配额，后台批量预生成并验证入库。用户刷题时优先取池，池子不足才实时生成。

收益：响应快、成本低、可复用、人工修正后永久生效。
配套：用户「举报此题有问题」→ 立即将该题移出池子并标记待复核。

## 5. 刷题模式设计

### 5.1 会话配置

- **范围**：手动选章节/知识点｜系统按薄弱点推荐｜整章随机
- **题型**：选择 / 填空 / 解答 / 混合
- **题量**：**不限**，用户随时可点「结束并结算」
- **反馈模式**：见下
- **计时**：开 / 关

### 5.2 两种反馈模式（需求核心）

| 模式 | 行为 |
|---|---|
| `逐题即时` | 答完立刻展示答案 + 分步解析 + 该选项对应的错因 |
| `整组延迟` | 一组 N 题（默认 10）全部做完后，给出正确率 + 逐题解析 |

### 5.3 判分策略

- **选择 / 多选**：客观判分
- **填空**：**必须做等价性判定**——`\frac{1}{2}` / `0.5` / `1/2` 判为同一答案；`x^2+C` / `x**2+C` 等价。
  用 SymPy 归一化比对；**判不了则降级为「自评」，绝不误判为错**。
- **解答题**：AI 按 rubric 分步给分，同时展示参考答案，并允许用户自评纠偏（AI 判分存在不稳定性，必须留人工口子）。

### 5.4 结算报告（需求明确要求）

- 正确率、总用时、**知识点维度掌握度可视化**（条形图 / 雷达图）
- **错题清单 + 逐题解析（核心产出）**：
  - 你的答案 / 正确答案
  - **错因归类**：概念不清 · 计算失误 · 方法不会 · 审题失误
  - 针对该错因的订正建议
- 一键导出 Markdown / PDF 错题本
- 错题自动进入间隔复习队列
- 更新知识点掌握度 → 影响下次推荐

### 5.5 掌握度模型

第一版**不上 BKT**，采用加权公式：

```
掌握度 = f(正确率, 题目难度, 用时, 遗忘衰减)
```

错题走 Leitner 间隔复习（box 1→5，间隔 1/2/4/7/15 天）。简单、可解释、足够用。

## 6. 真题演练模式设计

### 6.1 试卷模型

名称、年份、学校/考试类型、总分、时长、大题结构（题号 → 题型 → 分值 → 知识点）。

### 6.2 题目来源（三条路）

1. **手工录入器** —— 最可靠，优先实现
2. **PDF / 图片 → 多模态模型转 LaTeX → 人工校对** —— 已确认素材为扫描件，此路径为主
   **⚠️ 校对步骤不可省略**：OCR 数学公式错误率不低
3. 从已有题库导入

### 6.3 演练流程

模拟真实考试：可选计时 → 作答 → 交卷 → 客观题自动判分 + 解答题 AI 按得分点给分 → 总分 / 每题得分 / 评语 → 复盘。

### 6.4 复盘与闭环

错题 → 关联知识点 → **一键「针对此知识点刷题」→ 跳转刷题模式**。
支持重复演练，记录历史成绩与进步曲线。

> **版权提醒**：真题素材仅限本地个人复习使用，不做对外分发。

## 7. 技术架构

| 层 | 选型 |
|---|---|
| 后端 | Python 3.12 + FastAPI + SQLAlchemy + Pydantic |
| 数据库 | SQLite（单文件，便于备份） |
| 数学验证 | SymPy + mpmath |
| 前端 | React + Vite + TypeScript + Tailwind |
| 公式渲染 | **KaTeX**（全链路统一） |
| 图表 | ECharts |
| AI | 统一 Provider 抽象（OpenAI 兼容协议 → DeepSeek）；JSON Schema 强约束结构化输出；多模态用于真题 OCR |
| 相似度 | 暴力余弦（题量 < 10 万足够，无需向量库） |
| 运行 | `uvicorn` 本地服务 + 浏览器访问；后期可 PyInstaller 打包为 exe |

```
gaoshu-bank/
├─ docs/
│   ├─ PLAN.md                  # 本文档
│   └─ KNOWLEDGE_POINTS.md      # 知识点卡片（C1 优先）
├─ backend/
│   ├─ app/
│   │   ├─ main.py
│   │   ├─ api/                 # 路由：practice / paper / mistakes / stats
│   │   ├─ models.py            # SQLAlchemy 模型
│   │   ├─ schemas.py           # Pydantic schema
│   │   └─ services/
│   │       ├─ generator/       # 出题：prompt 模板、结构化生成
│   │       ├─ verifier/        # sympy_verifier / numeric_check / cross_check
│   │       ├─ grader/          # objective（等价性判定）/ ai_grader（解答题）
│   │       ├─ practice/        # 会话引擎、两种反馈模式、结算报告
```

## 8. 里程碑排期

| 阶段 | 内容 | 预估 |
|---|---|---|
| **M0** | 项目骨架、SQLite schema、AI Provider 封装（跑通一次「生成 → KaTeX 渲染」） | 1 天 |
| **M1** | 知识点卡片（C1 完整版）+ 生成→验证→入库流水线 + SymPy 验证器 | 2–3 天 |
| **M2** | 刷题 MVP：会话配置、两种反馈模式、选择/填空判分、结算报告 + 错题解析 | 2–3 天 |
| **M3** | 错题本、掌握度更新、推荐、Markdown/PDF 导出 | 1–2 天 |
| **M4** | 真题演练：试卷模型、PDF/图片录入器 + 校对、演练流程、AI 判分、与刷题模式打通 | 3–4 天 |
| **M5** | 增强：题目池预热、解答题判分调优、历史进步曲线、打包 | 按需 |

### 8.1 推进方式（重要）

**先做纵向切片**：只覆盖「极限与连续」一章，把
`生成 → 验证 → 做题 → 判分 → 错题解析`
全链路打通一遍。

这样第一天就能暴露真实风险（AI 出题正确率、填空等价判定、判分体验）。
反之，先铺满 12 章知识点卡片、最后才验证出题质量，风险极高。

## 9. 风险清单

| 风险 | 影响 | 应对 |
|---|---|---|
| **AI 出题答案错误** | 致命：用户信任崩塌 | 多层验证 + 题目池 + 人工抽检 + 用户一键举报下架 |
| 填空答案等价性难判 | 误判，体验差 | SymPy 归一化；判不了降级为自评，绝不误判 |
| 解答题 AI 判分不稳 | 分数不可信 | rubric 分步给分 + 展示参考答案 + 用户自评/申诉 |
| OCR 公式识别错误 | 真题不可用 | 强制人工校对环节；公式优先 LaTeX 化 |
| 成本与延迟 | 体验差 | 预生成池 + 缓存 + 流式输出 |
| 公式排版崩坏 | 题面不可读 | 全链路强制 LaTeX，KaTeX 统一渲染 |
| 真题版权 | 合规风险 | 仅本地个人复习使用，不分发 |
